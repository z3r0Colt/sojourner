SOJOURNER QOL ROADMAP — SESSION PROMPTS
========================================

One prompt per session. Copy everything between the ===== lines for the
session you are running and paste it into a fresh Claude Code session
opened in this project folder.

Before the first session:
  1. Commit the current working tree so each step's commits sit on a clean
     baseline (e.g. "Redesign: tokens, sidebar, reading toolbar, components").
  2. Close the running app and stop `npm run tauri dev` if it is running.

Run in order: 1, 2, 3a, 3b, 4, 5, 6a, 6b, 7.
Steps 1, 5, 6a, 6b, and 7 touch Rust, so start those with the app closed.


===== SESSION 1 · Step 1 · Foundations (F0.1–F0.5) =====

Context
- Project: Sojourner's Study Companion (Tauri 2 + Rust + React/TypeScript + Tailwind v4), repo at the current working directory.
- The implementation plan is the artifact "Sojourner QoL Roadmap":
  https://claude.ai/code/artifact/dc51ff46-043f-4d10-8b41-8e68e0db1616
  Read it first with the Artifact tool. It defines seven build steps, feature IDs (F0.x, W1–W4, F1.x, F2.x, F3.x, F4.2), and a per-feature "Done when".
- All decisions on that page are settled; take every "Recommend" as decided. Do not re-open them.

Task
- Build STEP 1 of the roadmap: Foundations. Features, in this order:
  F0.1 Passage text lookup
  F0.2 Settings API
  F0.3 Soft delete
  F0.4 Reference preview popover
  F0.5 Passage helpers
- Finish each one completely (behavior, data, files, shortcuts sheet and tutorial entries when a shortcut is added) before starting the next.
- If a feature's spec conflicts with what the code actually looks like, follow the code and note the deviation in your final report. Do not silently narrow scope.

How to work
- Before writing code, read the files each feature names on the page plus anything they import that you have not seen. Do not guess at signatures.
- Keep type-check clean as you go: run `npx tsc --noEmit` after each feature, and `npx vite build` after the step.
- For any change under src-tauri: the running dev instance locks the content database, so stop `npm run tauri dev` (and its tauri-app.exe) before `cargo check`, then restart it. Cargo is at ~/.cargo/bin.
- Commit after each completed feature with a message "<ID>: <feature name>" and a body listing user-visible changes. Do not amend or squash.
- Do not ask permission for reversible work inside the step. Stop and ask only if: a migration would drop or rewrite existing user data, a change would remove a feature the page does not say to remove, or you need a decision the page does not cover.

Definition of done for every feature (from the page)
- Type-check and Vite build pass; cargo check passes when Rust changed.
- Works in light, dark, and sepia; tokens only.
- Every new control is keyboard reachable with a focus state and an accessible name.
- Destructive actions confirm or offer undo; saves and deletes show a toast.
- New shortcuts appear in ShortcutsModal and TutorialSection the same day.
- A fresh install (empty user.db) shows a sensible empty state.
- If a migration was added: it is a new entry appended to USER_MIGRATIONS, and you have tested it by copying the current user.db, launching against the copy, and confirming existing notes, highlights, and prayers still appear.

When the step is done
- Run the app with `npm run tauri dev`, exercise each feature's "Done when" line by hand, and report exactly what you verified and what you could not.
- Final report, in this order: features completed with commit hashes; deviations from the page and why; anything left unfinished and what blocks it; suggested edits to the roadmap page. Keep it under 300 words.
- Then republish the roadmap artifact with each completed feature marked done in the index table (add a "Done" column if it does not exist yet), using the same artifact URL so the link is unchanged.
